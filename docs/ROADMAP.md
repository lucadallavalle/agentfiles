# Roadmap

In order; each step is one small PR. D-numbers refer to [ADR-001](adr/ADR-001_general-design.md). "Needs" are open questions to settle first; "Depends" are spiral-review features agentfiles waits for (D6), not works around.

## Planned work

- [x] **1. Foundations:** README, AGENTS.md, this roadmap, decision log, ADR-001; common documentation imported from spiral-review (D7); `grill` moved to `skills/`.
- [x] **2. Packaging** (D2, D3): one user-level plugin per harness carrying the skills (later hooks and commands); replaces the skill links of the former `install.sh`. This repo's git hooks are enabled by a `pnpm:devPreinstall` script in `package.json` (`pnpm install`).
  - Verified 2026-10-31 from official docs (code.claude.com, developers.openai.com, opencode.ai/v2) and the Claude Code 2.1.302 and OpenCode 2.0.32 CLIs; Codex rechecked with its CLI below:
    - Claude Code: marketplace `.claude-plugin/marketplace.json`; a plugin may be the marketplace root (`"source": "./"`), loading root `skills/`; `.claude-plugin/plugin.json` optional (the entry is the manifest). Skills namespaced `/<plugin>:<skill>`. No `version` → version is the commit SHA; third-party marketplaces don't auto-update by default. Install: `claude plugin install <plugin> --marketplace <owner/repo> -s user`. Check: `claude plugin validate --strict`.
    - Codex: portable manifest `plugin.json` at the plugin root (Agent Plugins schema), `.codex-plugin/plugin.json` as fallback; skills from root `skills/`. Marketplaces: `.agents/plugins/marketplace.json` (repo), `~/.agents/plugins/marketplace.json` (personal), `.claude-plugin/marketplace.json` (legacy-compatible). Install: `codex plugin marketplace add <owner/repo>`, then `codex plugin add <plugin>@<marketplace>`. Hooks `hooks/hooks.json`, on by default (`[features].hooks`); each hook runs only after the user trusts it. Codex loading a Claude-only `.claude-plugin/plugin.json` is undocumented.
    - Codex CLI 0.163.0 (2026-11-02): `version` is optional in the portable `plugin.json` (required only in `.codex-plugin/plugin.json`); without it the install is cached as `1.0.0`, and `codex plugin marketplace upgrade` still refreshes it to the new commit. The root `plugin.json` alone works, no `.codex-plugin/`. `marketplace add owner/repo@ref` clones into `~/.codex/.tmp/marketplaces/<marketplace>` and reads `.agents/plugins/marketplace.json`; a local entry with path `./` installs the root. Skills are namespaced `<plugin>:<skill>`. `codex debug prompt-input` shows the model-visible skill list: `agents/openai.yaml` removes the skill from it, app-server `skills/list` still shows it enabled, and `$agentfiles:grill` loads it in a session. Claude Code ignores the root `plugin.json`.
    - OpenCode: loads `SKILL.md` from `~/.config/opencode/skills`, `~/.claude/skills`, `~/.agents/skills`, extra `skills` config entries (paths or HTTP catalogs). Skill IDs are flat (no namespace; later source wins). Plugins are npm or git JS packages (`opencode plugin add github:<owner/repo>`); a server plugin adds skills only through code (`ctx.skill.transform`).
    - OpenCode plugin install (2.0.32): the docs only say the SDK comes from the plugin's `@opencode/plugin` dependency; Bun, `.js`→`.ts` specifiers, dependency install and `prepare` are undocumented. Observed: `plugin add` installs with a bundled npm (no devDependencies); a git source with `workspaces` or a `build`, `prepare`, `prepack`, `preinstall`, `install` or `postinstall` script fails (`git dep preparation failed`); `.ts` source loads with `.js` specifiers; plugin-added skills bypass frontmatter, so manual-only needs `autoinvoke: false`; on a duplicate ID with `~/.claude/skills`, either source won depending on load order. Rechecked with 2.2.5 (2026-11-02): install from git works, the plugin is `active`, `grill` has `autoinvoke: false`; `plugin check` and `plugin update` ignore git plugins, and removing then re-adding the same branch reuses the cached commit (a new ref, such as a commit SHA, fetches).
    - `pnpm:devPreinstall` (pnpm.io/scripts, pnpm 12.11.2, 2026-11-02): runs on `pnpm install` in the root project only, never for a dependency; a fresh clone plus `pnpm install` sets `core.hooksPath`; OpenCode 2.2.5 installs the branch from git and the plugin is `active`.
    - `disable-model-invocation: true`: Claude Code and OpenCode honor it (OpenCode: `@skill-id` loads it by hand); Codex needs `agents/openai.yaml` in the skill with `policy.allow_implicit_invocation: false` (`$skill` still works).
  - Decided: layout, names, versioning, OpenCode plugin, skill IDs, generated manifests, gate validation, PR split ([decision log](decisions.md)).
  - Depends: spiral-review `init` installs its own plugin; the two plugins must not collide (skill and command names, hook order).
- [x] **3. User-level config** (D3, D4): the CLI's first command, `doctor` / `doctor --fix`, for user-level config: global instructions, settings and permissions per harness; hooks and MCP servers go in the plugins.
  - Verified 2026-11-02 from official docs (code.claude.com, learn.chatgpt.com, opencode.ai/v2) and the Claude Code 2.1.302, Codex 0.163.0 and OpenCode 2.2.5 CLIs against a fake home:
    - Claude Code: instructions `~/.claude/CLAUDE.md` and `~/.claude/rules/*.md`; `@path` imports (`@~/…`, absolute, 4 hops) load at user level without a prompt. Settings `~/.claude/settings.json`, strict JSON, arrays concatenate across scopes, no user-level include; the harness rewrites it (`/config`, `/model`, plugin installs). User MCP servers live in `~/.claude.json`, rewritten constantly. Plugins carry hooks and MCP servers, not permissions. `${VAR}` expands in `.mcp.json`, not in settings `env`. `CLAUDE_CONFIG_DIR` moves everything.
    - Codex: instructions `$CODEX_HOME/AGENTS.override.md`, else `AGENTS.md` (`~/.codex`); no include (`@` stays literal); `developer_instructions` reaches the prompt. Settings `~/.codex/config.toml`, rewritten by Codex (trust, marketplaces, `mcp add`, comments kept); profiles need `--profile` and replace arrays. Command rules: Starlark `prefix_rule` in `rules/*.rules`, the TUI writes `default.rules`, most restrictive wins. No `${VAR}`: `env_vars`, `bearer_token_env_var`, `env_http_headers`. Plugins carry hooks (each trusted via `/hooks`) and MCP servers.
    - OpenCode (V2): instructions `~/.config/opencode/AGENTS.md`, no `CLAUDE.md`; `instructions` array (`~/`, absolute, globs, URLs) concatenates across layers. Settings `opencode.json` / `.jsonc`, rewritten and reformatted by `mcp add` and `plugin add`. Permissions: ordered `{action, resource, effect}`, last match wins. `{env:VAR}`, `{file:…}`. Plugins add MCP servers (`ctx.mcp.transform`) and permissions only in code.
  - Decided ([decision log](decisions.md)): tracked entries with one drift rule (files and JSON/TOML keys, hash in a state file, edits reported, never overwritten, no managed blocks); plugins carry hooks, MCP servers, commands, settings carry the rest; env references only; a neutral shell-prefix permissions list; first content; `config/` and `~/.config/agentfiles/instructions.md`; spiral-review's config is never tracked; the CLI starts here.
  - PRs: [plan 001](plans/001_user-level-config.md) C01–C05: CLI scaffold and bundle; core; Claude Code, Codex, OpenCode adapters. Codex loads every `rules/*.rules`, stricter wins (verified 2026-11-03).
- [ ] **4. CLI `agentfiles`** (D5, D8): on the scaffold and `doctor` from step 3:

    - spiral-review R14, scriptable and idempotent `init` (all answers as flags), changing only its own keys in harness settings: in its roadmap, not built; its MVP `init` is Claude Code only.
    - spiral-review R13, user-level config and `.git/info/exclude` for foreign repos, needed by `attach`: in its roadmap, not built.
    - spiral-review user-level config (`~/.config/spiral-review`), where `bootstrap` passes the reviewer model to `init`: an MVP item in its roadmap, not built.
    - spiral-review repo config: the instructions file is `REVIEW.md` (decided); whether to keep `.spiral-review.toml` is open there (R13). `scaffold` must get both from spiral-review, not write them itself.
