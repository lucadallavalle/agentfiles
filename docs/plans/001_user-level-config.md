## Technical Approach

The CLI (`src/cli/`) parses arguments only. `src/core/` reads `config/`, keeps the state file and gives each shipped or tracked entry one state: in sync, or one of five kinds of drift: missing (shipped, absent, untracked), outdated (tracked, unchanged, shipped value newer), edited (tracked, changed or removed by the user), unshipped (tracked, unchanged, no longer shipped), conflict (untracked, the machine already has a different value; an equal value is adopted as in sync). Each adapter maps the neutral config onto its harness's files and key shapes and edits them in place, keeping comments and formatting. Mechanism, content and paths are settled in the decision log; this plan adds the order and the decisions below.

## Implementation

`doctor` without `--fix` never writes. `--fix` writes missing and outdated entries, removes unshipped ones, and only reports edited and conflict ones. Every run is idempotent.

Output is for people: one plain-text line per entry not in sync (`<harness> <entry> <state>`); edited and conflict lines show the shipped value and how to resolve them (restore it, or remove your value); a one-line summary. No `--json`: `bootstrap` (step 4) calls the core, not the CLI. Exit codes: `doctor` 0 in sync, 1 on any drift, 2 on error; `--fix` 0 once everything it may fix is fixed (edited and conflict entries remain, printed), 2 on error. Accepting an edit means restoring the value or changing `config/`; no adopt command.

Harnesses and paths:

- A harness is present when its config directory exists or its binary is on `PATH`; otherwise one line `<harness> not installed, skipped`, not drift. Binary only: `--fix` creates the directory.
- Honored, as each harness does: `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `XDG_CONFIG_HOME` (OpenCode and `~/.config/agentfiles`); `XDG_STATE_HOME` for the state file.
- The `@` import and the OpenCode `instructions` element name the real location of `instructions.md`: `~/…` under `HOME`, else absolute.
- State entries are keyed by absolute path; an entry whose location is no longer a target is unshipped (removed only if unchanged).

Error paths (C02 tests the first four):

- A file that doesn't parse (JSON, TOML, the state file): that harness reports an error and is skipped, the others run; `--fix` never writes it; exit 2.
- No state file: entries are classified afresh; equal values are adopted as in sync, different ones are conflicts.
- A symlinked target is resolved and the real file written, so the link survives.
- Writes are atomic (temp file in the same directory, rename, mode kept); the state file is written last, so an interrupted run is adopted on the next one.
- A harness running during `--fix` may rewrite its file and drop our entries; the next `doctor` reports them edited. Documented in the README, not prevented.

## Testing Strategy

- Unit: every state per entry kind (file, JSON key, TOML key, list element); removal of unshipped entries; idempotency (`--fix` twice changes nothing).
- Fake home: every test runs the CLI with `HOME` and the variables from "Harnesses and paths" pointing at a temp directory. Fixtures with comments, reformatted files and foreign keys must survive untouched.
- Fake home for real harness checks: `export HOME=$(mktemp -d); export CLAUDE_CONFIG_DIR=$HOME/.claude CODEX_HOME=$HOME/.codex XDG_CONFIG_HOME=$HOME/.config XDG_STATE_HOME=$HOME/.local/state`, then `node bin/agentfiles.js doctor --fix`. The machine has only pnpm, so npm runs as `pnpm dlx npm@11`. OpenCode checks need `--standalone`, or they ask the background service, which uses the real home.
- Real harnesses, as PR evidence like step 2, in the Accept lines below. Claude Code permission rules have no non-interactive check: unit tests only.

## Acceptance Criteria

- `agentfiles doctor --fix` on a fake home with all three harnesses writes the shipped config; a second run changes nothing; `doctor` then reports no drift.
- Editing a tracked entry makes `doctor` report it and `--fix` leave it alone.
- No literal secret can enter `config/` without failing the gate.
- All tests passing
