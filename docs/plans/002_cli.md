## Technical Approach

`doctor` keeps one output and the exit codes of plan 001 and gains groups, in `--fix` order: the CLI's clone, plugins (their installs rewrite harness settings, so they go before the config merges), user-level config and the documentation copy, then `repo`. Each adapter gains an optional plugin part: read the installed commit, install, update, all through the harness's CLI with the run's environment. The core owns the CLI's commit, the skip rule and the clone; `src/core/repo.ts` owns owned-repo detection and repo drift, reusing the tracked-entry states without the state file.

### Risks & Trade-offs

| Risk/Trade-off                                                 | Impact | Mitigation                                                                   |
| -------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------- |
| `main` moves between the fast-forward and Claude Code's update | Low    | `--fix` reports it outdated with `main`'s commit; the next `--fix` converges |
| A harness CLI changes its output or flags                      | Medium | Parsing only in adapters; each adapter chunk carries real CLI output         |
| A harness session running during `--fix`                       | Low    | The plugin applies on the next session; README says so                       |
| `AGENTFILES_COMMIT` installs an older commit                   | Low    | Only commits on `origin/main`; documented under README Development only      |
| One of the two unverified facts fails                          | Medium | Each chunk below names its fallback; using one is an amendment               |

## Implementation

Output lines follow plan 001: `<harness> plugin <state>` with both commits when outdated; `agentfiles clone behind main` / `can't check main (offline)` (no error) / `agentfiles clone not on main, skipped`; `repo <path> <state>` with paths relative to the repo root. `repo` is silent outside a git repo, in a foreign repo and in this repo. `--fix` never commits.

## Testing Strategy

- Unit: every plugin state per adapter with stub harness binaries on `PATH` that record their arguments; the skip rule (dirty, off `main`, override); repo drift states in temp git repos with SSH and HTTPS remotes; the floor check; `bootstrap` prerequisites and link; idempotency (`--fix` twice).
- Fake home, as plan 001: `export HOME=$(mktemp -d)`, then `export CLAUDE_CONFIG_DIR=$HOME/.claude CODEX_HOME=$HOME/.codex XDG_CONFIG_HOME=$HOME/.config XDG_STATE_HOME=$HOME/.local/state AF=$PWD/bin/agentfiles.js && mkdir -p $CODEX_HOME`; `CLAUDE_CODE_PLUGIN_CACHE_DIR` unset; OpenCode commands with `--standalone`.
- Plugin chunks run from the PR branch with `git fetch origin` and `AGENTFILES_COMMIT=$NEW`, `NEW=$(git rev-parse origin/main)`; `OLD` is C01's merge commit, whose `skills/grill/SKILL.md` differs from `NEW`'s (C02 edits it), so a move is visible in the installed files.
- C01–C04 change nothing a harness loads: their Accept runs the bundle in a fake home, no harness CLI (decision log).

## Acceptance Criteria

- On a fresh fake home with all three harnesses, the one-liner installs the plugins at the CLI's commit, merges the config and writes the documentation copy; a second run changes nothing; `doctor` then exits 0.
- In an owned repo, `doctor` reports missing, outdated and edited documentation copies; `--fix` writes the first two only.
- The bundle exits 2 with a message on Node 20 and runs on Node 22.
- All tests passing
